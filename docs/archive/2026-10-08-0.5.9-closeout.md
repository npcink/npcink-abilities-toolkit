## Durable Lessons

1. **Plugin Check enforces literal translation arguments as errors.**
   Rendering contract data through dynamic `esc_html__()` calls produced two
   ERROR-level `WordPress.WP.I18n.NonSingularStringLiteralText` findings that
   failed the release lane — the same blind spot the advisory review had
   flagged from the maintainability side, one day earlier. The durable
   pattern for localizing catalog-style contract data: a translation map
   class with one literal `__()` call per string keyed by the English
   contract text, falling back to the original for unknown entries. Tooling
   then rediscovers the entries and the packaged plugin passes review.
2. **The CI-only ratchets need local pre-checks when adding files.** #213's
   first push failed both php CI jobs because `composer
   check:phpstan-ratchet` (not part of `test:all`) counted four
   provably-true defensive guards in the new `Welcome_Notice` against the
   changed-file conservation rule. Fixed by removing the provable guards and
   keeping the harness guards; the pre-check rule is now in AGENTS.md (#214).
3. **In-flight sibling-repo work can pause the shared verification site.**
   The real-site smoke leg fatalled while the symlinked `npcink-governance-core`
   working tree (`fix/ux-round2`) carried a static-call bug at
   `rest_api_init`. No Toolkit change was involved; the sibling edit landed
   and the lane passed end to end. Operational takeaway: before a release
   lane run, a failing site bootstrap should be attributed across all
   symlinked plugins first — the toolkit is only one of five dev links on
   `magick-ai`.
